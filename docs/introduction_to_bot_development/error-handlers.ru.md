Обработчик ошибок — это асинхронная функция, принимающая объекты `update` и `context`. Она содержит логику обработки возникающих ошибок во время работы бота.

> **Примечание**: `update` может быть `None`, если исключение возникло при рассылке уведомлений с помощью обработчика [`send`](../api_reference/core/screen.md#hammett.core.screen.Screen.send) (см. [Задачи, выполняемые по расписанию](advanced.md#задачи-выполняемые-по-расписанию)).

Для того чтобы функция стала обработчиком ошибок, ее необходимо зарегистрировать, передав ее аргументу `error_handlers` при создании объекта класса [`Bot`](../api_reference/core/bot.md#hammett.core.bot.Bot) (см. [Сборка бота и запуск](assemble-and-run-bot.md)). Он представляет собой список, где перечисляются функции, которые должны перехватывать возникающие исключения.

> **Примечание**: в списке может быть перечислено несколько обработчиков ошибок. В этом случае при возникновении исключений обработчики будут вызываться по очереди в том порядке, в котором они перечислены в `error_handlers`.

Для создания обработчика нужно объявить асинхронную функцию, принимающую параметры `update` и `context`. Когда возникает исключение, зарегистрированные обработчики вызываются один за другим. ## <a name="встроенный-обработчик"></a> Встроенный обработчик

В Hammett уже есть встроенный обработчик, который позволяет отлавливать и логировать следующие исключения:

1. `telegram.error.BadRequest: Query is too old and response timeout expired or query id is invalid`;
2. `telegram.error.BadRequest: Message is not modified`;
3. `telegram.error.TimedOut: Timed out`.

Обработка этих исключений выключена по умолчанию. Для активации встроенных обработчиков нужно добавить в модуль `settings.py` следующий атрибут:

{% include-markdown 'examples/error_handlers/error_handler_conf_setting.md' %}

Каждый ключ словаря `ERROR_HANDLER_CONF` представляет одно из исключений выше. Значением каждого ключа может быть либо `True` для активации встроенного обработчика, либо `False` для его выключения.
