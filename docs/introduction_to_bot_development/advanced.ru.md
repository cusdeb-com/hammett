Hammett предоставляет дополнительные инструменты, которые помогают расширять функциональность бота. Этот раздел описывает несколько полезных механизмов, которые можно использовать при разработке комплексных ботов. Изучать его следует после ознакомления с базовыми возможностями фреймворка.

## <a name="сохранение-контекста"></a> Сохранение контекста

Когда пользователь инициирует разговор с ботом (к примеру, посредством команды `/start)`, бот находится в исходном состоянии `None` (см. [Состояния](states.md)). Далее пользователь может переключать бота между разными состояниями — это определяет, как бот будет себя вести в дальнейшем.

_Контекст взаимодействия между пользователем и ботом_ используется для хранения данных, связанных с пользователем, чатом или состоянием бота и хранится на стороне бота в оперативной памяти. Таким образом, пользователь может продолжить работу с ботом в любой момент с того места, на котором остановился, но только до тех пор, пока бот не будет перезапущен (на сервере). Как только бот перезапускается, контекст теряется, и пользователю требуется снова инициировать разговор с ботом с помощью команды `/start`. В промышленной среде такое недопустимо: перезапуск ботов не должен влиять на пользователей.

## <a name="управление-отрисовкой-метод-render"></a> Управление отрисовкой (метод render)

В Hammett любая отрисовка экранов сводится к вызову их метода [`render`](../api_reference/core/screen.md#hammett.core.screen.Screen.render). Переопределение метода может понадобиться, если необходимо добавить какую-то логику перед каждой отрисовкой экрана вне зависимости от того, через какой обработчик — [`move`](../api_reference/core/screen.md#hammett.core.screen.Screen.move), [`jump`](../api_reference/core/screen.md#hammett.core.screen.Screen.jump), [`move_along_route`](../api_reference/core/mixins.md/#hammett.core.mixins.RouteMixin.move_along_route), [`jump_along_route`](../api_reference/core/mixins.md/#hammett.core.mixins.RouteMixin.jump_along_route), [`send`](../api_reference/core/screen.md#hammett.core.screen.Screen.send) или [`start`](../api_reference/core/mixins.md/#hammett.core.mixins.StartMixin.start) — он был вызван.

Например, в демо [HammettQuizBot](https://t.me/HammettQuizBot) метод [`render`](../api_reference/core/screen.md#hammett.core.screen.Screen.render) переопределяется для сброса текущего вопроса и общего количества правильных ответов после перехода на главное меню: не имеет значения, как был вызван экран главного меню, состояния опроса будут сброшены после перехода на него.

## <a name="хранение-данных-пользователя-на-стороне-бота"></a> Хранение данных пользователя на стороне бота

Комплексному боту требуется хранить на своей стороне различную информацию, связанную с пользователями. В простейшем случае это могут быть данные для постраничного перехода. Например, в боте есть 50 разделов с книгами, которые разбиваются по пять на один экран, и пользователь просматривает их, нажимая кнопки "Назад" и "Вперед". Чтобы реализовать это, необходимо каждый раз сохранять номер текущего экрана в хранилище на стороне бота, которое закреплено за конкретным пользователем, где действия других пользователей никак не влияют на него.

С этим хранилищем можно работать через `context.chat_data`, когда нужно хранить информацию, специфичную для каждого чата, и `context.user_data`, когда нужно хранить информацию, специфичную для каждого пользователя. С их помощью вы можете сохранять информацию, полученную в одном обработчике, и передавать ее в другой, выполняя над ними операции, как над обычными словарями. Ниже приведен пример, как сохранить полученную полезную нагрузку для ее "безопасного" извлечения из хранилища:

{% include-markdown 'examples/advanced/getting_payload_safely.md' %}

Таким образом, если произойдет сбой на стороне Telegram и пользователь _повторно_ нажмет на кнопку, то будет выброшено исключение [`PayloadIsEmpty`](../api_reference/core/exceptions.md#hammett.core.exceptions.PayloadIsEmpty) (см. [Полезная нагрузка](screens.md#полезная-нагрузка)), после чего будет получена и возвращена полезная нагрузка, сохраненная в словаре `context.user_data` под ключом `MY_PAYLOAD_KEY`.

Также существует словарь `context.bot_data`, с которым можно работать по тому же принципу, но в отличие от `context.chat_data` и `context.user_data`, это единственный словарь для вашего бота.

> **Примечание**: все данные, записанные в `context.bot_data`, `context.chat_data` и `context.user_data`, хранятся в оперативной памяти и удаляются после завершения процесса бота. Для того чтобы сохранять их между перезапусками бота, используйте [сохранение контекста](advanced.ru.md#сохранение-контекста).

Это связано с тем, что встроенная реализация сохранения состояния может работать только с **сериализуемыми данными**.

Однако этого делать **нельзя**, т.к. экраны являются синглтонами. Это означает, что изменение значения атрибута одним пользователем ведет к изменению его значения у всех пользователей.

## <a name="вебхуки"></a> Вебхуки

Существует два способа получения обновлений от сервера Telegram: _поллинг_ (polling) и _вебхук_ (webhook). По умолчанию боты используют поллинг, _опрашивая_ сервер Telegram на наличие обновлений в процессе работы. Поллинг универсален: он подходит как _для разработки_, так и для _эксплуатации бота в промышленной среде_. Но за универсальность приходится платить задержками, которые могут отразиться на отзывчивости бота, т.к. обновления не поступают в режиме реального времени.

Вебхук, в свою очередь, позволяет автоматически получать обновления от сервера Telegram через выставленный ботом URL, на который в случае появления обновлений отправляются POST-запросы. Вебхук подходит исключительно для эксплуатации бота в промышленной среде и гарантирует получение обновлений в режиме реального времени.

Для того чтобы переключиться на этот способ получения обновлений, необходимо указать несколько параметров конфигурации и настроить веб-сервер. Ниже приведен пример `settings.py` для настройки вебхука:

## <a name="функция-render-template-from-string"></a> Функция render_template_from_string

Функция [`render_template_from_string`](../api_reference/template.md/#hammett.template.render_template_from_string) представляет собой готовый инструмент для формирования динамических описаний экрана с помощью шаблонного движка [Jinja2](https://jinja.palletsprojects.com/en/stable/).

Функция принимает два аргумента — _шаблон_ (template) и _контекст_ (context). Шаблон может содержать переменные, которые имеют следующий вид: `{{ variable }}`. В результате работы функции переменные будут заменены на значения, взятые из контекста. Контекст представлен словарем: его ключами являются названия переменных, а значениями — текст для подстановки.

Ниже приведен пример использования для формирования описания экрана с информацией о дате окончания подписки:

{% include-markdown 'examples/advanced/render_template_from_string_usage.md' %}

Помимо переменных в шаблоне могут содержаться _управляющие конструкции_ (control structures). Управляющая конструкция относится ко всем элементам, которые контролируют поток программы — условным операторам (таким как `if`/`elif`/`else`), циклам `for`, а также к таким вещам, как макросы и блоки. При использовании стандартного синтаксиса управляющие конструкции располагаются внутри блоков `{% ... %}`. Читайте подробнее, как использовать управляющие конструкции в шаблонах в статье [Template Designer Documentation](https://jinja.palletsprojects.com/en/stable/templates/).

> **Примечание**: функция [`render_template_from_string`](../api_reference/template.md/#hammett.template.render_template_from_string) является безопасной, т.е. если в шаблоне будет переменная, значение которой не указано в контексте или наоборот — значение указано для переменной, которая опущена в шаблоне, то переменная без значения не отобразится, а лишнее значение в контексте будет проигнорировано. Другими словами, функция не выбросит исключение, если произойдет рассинхрон между шаблоном и контекстом.

## <a name="start-маркеры"></a> Start-маркеры

В комплексных ботах нужно средство для отслеживания источников, из которых пользователи попадают в ботов. Для решения этой задачи Hammett предлагает так называемые start-маркеры — механизм, позволяющий передавать Telegram-боту информацию в формате `key=value` прямо в ссылке на бота. К примеру, для разных каналов распространения нашего бота [TurorIn.Tech](https://t.me/TutorInTechBot?start=mkdocs) мы используем разные ссылки, чтобы отслеживать эффективность каждого из этих каналов. Ссылка в био нашей Instagram-страницы, в свою очередь, выглядит так:

Механизм представлен классом [`StartMarker`](../api_reference/start_marker.md#hammett.start_marker.StartMarker) из модуля [`hammett.start_marker`](../api_reference/start_marker.md). ## <a name="настройки-сетевого-интерфейса"></a> Настройки сетевого интерфейса

Чтобы управлять максимальным временем ожидания ответа от сервера Telegram (в секундах) при отправке сообщений, можно воспользоваться параметром конфигурации `SEND_METHODS_READ_TIMEOUT`. По умолчанию его значение равно `5` секундам.

Чтобы управлять максимальным временем ожидания ответа от сервера Telegram глобально, можно воспользоваться параметром конфигурации `APPLICATION_BUILDER_READ_TIMEOUT`. По умолчанию его значение равно `5.0` секундам.
