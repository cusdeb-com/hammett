    Экраны

    Экран — это абстракция над обычным Telegram-сообщением для управления его состоянием. Экраны представляют собой классы, которые наследуются от класса Screen из модуля hammett.core.screen. Этот класс решает две в равной степени важные задачи:

    1. предоставление возможности для отрисовки и дальнейшей перерисовки контента;
    2. предоставление механизма перехода от одного экрана к другому.

    Экран может состоять из следующих компонентов, которые представлены соответствующими атрибутами класса Screen:

    1. cover или document — обложка (изображение) или документ, которые должны быть отправлены в чат пользователю. Если экран имеет обе эти составляющие, приоритет у документа будет выше, поэтому он отправится пользователю в чат, а изображение будет проигнорировано.
    2. description — текст сообщения, который может содержать HTML-теги (см. здесь, какие теги могут использоваться в описаниях).
    3. keyboard — одна или более кнопок, формирующих клавиатуру экрана (см. Клавиатура и кнопки).

    У экрана должен быть хотя бы один из следующих компонентов: обложка (cover), описание (description) или документ (document).

    Примечание: на экране эти компоненты располагаются строго в том порядке, в котором они перечислены в списке выше. Повлиять на этот порядок нельзя.

    Примечание: максимальное количество кнопок на клавиатуре по горизонтали составляет 8. Общее количество кнопок, отображаемых одновременно, составляет 100. Используйте этот источник в качестве дополнительного, чтобы перепроверить эту информацию.

    Компоновка экрана#

    Чтобы определить компоненты экрана (см. предыдущий раздел), есть три способа:

    1. Статически через атрибуты класса Screen. Это самый простой способ компоновки экрана, предполагающий хардкодинг непосредственных значений в атрибутах класса Screen: cover, document и description. Он подходит в тех случаях, когда нужно отправлять контент пользователю в чат без каких-либо условий.

      Вот пример самого простого экрана с изображением и текстом:

      from hammett.core import Screen


class MyScreen(Screen):
   cover = 'https://some/url/path/to/image.jpg'
   description = 'This is a description'

    2. Динамически через специальные методы класса Screen. Этот способ необходим при работе с динамическим контентом, например, когда он запрашивается через API. Суть этого способа в том, чтобы переопределять методы экрана и уже там программировать нужное поведение.

      Для динамического управления атрибутом cover используется метод get_cover, для атрибута description — get_description, а для document — get_document. Для клавиатуры методом управления является add_default_keyboard.

      Вот пример того же простого экрана с изображением и текстом, но с использованием методов вместо атрибутов:

      from hammett.core import Screen


class MyScreen(Screen):
 async def get_cover(self, update, context, **kwargs):
     return 'https://some/url/path/to/image.jpg'


 async def get_description(self, update, context, **kwargs):
     return 'This is the description'

    3. Через RenderConfig. Cм. Работа с API.

    Настройка компонентов экранов#

    У экрана есть атрибуты, которые позволяют настраивать его компоненты:

    1. Кеширование обложек. Если большинство экранов бота используют одну и ту же обложку, можно включить ее кеширование, чтобы ускорить рендеринг экранов. Для этого нужно атрибут cache_covers установить в True. Таким образом, указанная обложка будет кешироваться вне зависимости от того, что атрибуту cover передано: URL на внешний ресурс или путь к файлу.
    2. Уточнение формата описаний. Атрибут html_parse_mode указывает, в каком формате передан атрибута description текст описания экрана: в HTML или Markdown.
    3. Скрытие клавиатуры. В некоторых случаях может потребоваться скрывать клавиатуру у экранов, которые остаются в истории. Для этого нужно атрибут hide_keyboard установить в True (см. Скрытие клавиатуры).

    Клавиатура и кнопки#

    Здесь и далее речь будет идти об inline-клавиатурах.

    Клавиатура имеет свой тип Keyboard, определенный в модуле hammett.types:

    from hammett.core import Button

Keyboard = list[list[Button]]

    Она является списком, который представляет ряды клавиатуры. Внутри этого списка также находится список, представляющий положение кнопок в ряду. И уже в этом вложенном списке находится кнопка — экземпляр класса Button из пакета hammett.core.button.

    Кнопки находятся в клавиатуре и делятся на несколько типов в зависимости от типа источника действия.

    Источники действий и его типы#

    У каждой кнопки есть атрибут source, который позволяет связать кнопку с ее действием или обработчиком. Этот атрибут указывает на источник действия, которое должно быть выполнено при нажатии на кнопку.

    Наряду с атрибутом source есть также атрибут source_type, название которого говорит само за себя — он необходим для уточнения типа того или иного источника.

    В роли источника (source) могут выступать:

    1. Экран. Он предназначен для перехода на указанный экран.

      Для этого источника используются следующие типы источников:

      • MOVE_SOURCE_TYPE — нужен для перехода с текущего экрана на другой с его перерисовкой на новый экран. Является оберткой для вызова следующего кода:

        await MyScreen().move(update, context)

      • JUMP_SOURCE_TYPE — нужен для перехода с текущего экрана на другой с отправкой другого экрана в виде нового сообщения. Является оберткой для вызова следующего кода:

        await MyScreen().jump(update, context)

      • MOVE_ALONG_ROUTE_SOURCE_TYPE — нужен для перехода с текущего экрана на другой с его перерисовкой на новый экран, когда текущий экран зарегистрирован в одном состоянии, а другой — в другом состоянии. Является оберткой для вызова следующего кода:

        await MyScreen().move_along_route(update, context)

      • JUMP_ALONG_ROUTE_SOURCE_TYPE — нужен для перехода с текущего экрана на другой с отправкой другого экрана в виде нового сообщения, когда текущий экран зарегистрирован в одном состоянии, а другой — в другом состоянии. Является оберткой для вызова следующего кода:

        await MyScreen().jump_along_route(update, context)

      Примечание: типы источников MOVE_ALONG_ROUTE_SOURCE_TYPE и JUMP_ALONG_ROUTE_SOURCE_TYPE доступны для экранов, которые наследуются от RouteMixin (см. Переключение между состояниями).

    2. Метод экрана, зарегистрированный в качестве обработчика (см. Обработчики). Он предназначен для выполнения кода внутри этого метода.

      Для этого источника в качестве значения source_type используется HANDLER_SOURCE_TYPE. Он нужен для вызова переданного обработчика при нажатии на кнопку.

    3. Ссылка. Она предназначена для осуществления перехода на сторонний ресурс.

      Для этого источника используются следующие типы источников:

      • URL_SOURCE_TYPE — используется для перехода по ссылке на сторонний ресурс.
      • WEB_APP_SOURCE_TYPE — используется для перехода по ссылке на сторонний ресурс, не выходя из приложения Telegram (см. Telegram Mini Apps).

    Полезная нагрузка#

    Когда клавиатура с кнопками создается динамически, необходимо средство, которое поможет понять, какая именно кнопка была нажата. Этим средством является полезная нагрузка (payload) — информация, которую может содержать каждая кнопка. Если у кнопки есть полезная нагрузка, то она станет доступна в обработчике сразу после нажатия на эту кнопку. Для ее получения нужно вызвать метод экрана get_payload. Однако стоит помнить, что после того как полезная нагрузка была получена, она удаляется из хранилища, и ее повторный запрос будет приводить к исключению PayloadIsEmpty.

    Ниже приведен пример получения полезной нагрузки в обработчике:

    from hammett.core.handlers import register_button_handler


@register_button_handler
async def handler(self, update, context):
    payload = await self.get_payload(update, context)  # successfully got payload
    await self.get_payload(update, context)  # PayloadIsEmpty
    ...

    Примечание: при неудачной попытке получение полезной нагрузки также может быть выброшено исключение FailedToGetDataAttributeOfQuery, сигнализирующее об отсутствии данных в объекте CallbackQuery.

    Примечание: обратите внимание, что типом полезной нагрузки может быть только str.

    Ниже приведен пример передачи полезной нагрузки с кнопкой:

    from hammett.core import Button
from hammett.core.constants import SourceTypes


Button('To my screen', MyScreen,
       source_type=SourceTypes.MOVE_SOURCE_TYPE,
       payload='This is my payload.')

    Теперь, если после нажатия этой кнопки в ее обработчике вызвать метод get_payload, он вернет 'This is my payload.'.

    Ниже приведен пример, где значение, переданное с полезной нагрузкой, подставляется в качестве описания экрана MyScreen:

    from hammett.core import Screen


class MyScreen(Screen):
    async def get_description(self, update, context, **kwargs):
        payload = await self.get_payload(update, context)
        return payload

    См. live-пример бота HammettDynamicKeyboard с демонстрацией работы этого функционала.

    Управление видимостью кнопок#

    Атрибут hiders класса Button управляет видимостью той или иной кнопки в зависимости от роли пользователя. Читайте раздел Hider-механизм, чтобы узнать, как это работает.

    Кнопки в уведомлениях#

    Если у кнопки есть полезная нагрузка, и она принадлежит экрану, который отправляется с использованием обработчика send (см. Задачи, выполняемые по расписанию), то эта кнопка должна иметь атрибут chat_id, необходимый для корректной передачи полезной нагрузки. Ниже приведен пример кнопки с указанием этого атрибута:

    from hammett.core import Button
from hammett.core.constants import SourceTypes


Button('To my screen', MyScreen,
      chat_id=123,
      source_type=SourceTypes.MOVE_SOURCE_TYPE,
      payload='This is my payload.')

    Скрытие клавиатуры#

    Когда для перехода от одного экрана к другому используется метод jump, то экран, на который осуществляется переход, появляется в виде нового сообщения, а экран, с которого осуществился переход, остается в истории (см. Переходы между экранами). Hammett дает разработчикам возможность автоматически скрывать клавиатуру у экранов, которые остаются в истории, сохраняя ее только у последнего экрана. Это делает историю сообщений более чистой и избавляет от потенциальных ошибок, которые могут возникнуть, когда пользователь нажимает на кнопки предыдущих сообщений.

    Чтобы включить скрытие клавиатуры, параметр конфигурации SAVE_LATEST_MESSAGE и атрибут hide_keyboard у каждого из экранов должны быть установлены в True. Для реализации последнего рекомендуется использовать базовый экран (см. Лучшие практики).

    Однако заметьте, что удаление клавиатуры у более чем одного предыдущего сообщения не поддерживается. Поэтому, если вы включите эту возможность через какое-то время после запуска вашего бота, не следует ожидать, что клавиатуры всех экранов, сохранившихся в истории, скроются сразу после следующего вызова jump.

    Примечание: данная возможность не всегда может корректно работать в веб-версии Telegram. Там возможен случай, когда клавиатура экрана сохраняется, но перестает работать. Чтобы это исправить, нужно обновить страницу браузера. В приложении эта проблема встречается реже. Также имейте в виду, что нельзя гарантировать 100% работоспособность этого механизма из-за возможных проблем на стороне Telegram.

    См. live-пример бота HammettHideKeyboardBot с демонстрацией работы этого функционала.

    Переходы между экранами#

    Базовый класс Screen предоставляет своим наследникам два следующих метода для стандартного перехода между экранами:

    1. move используется, когда нужно перейти от текущего экрана к другому, тем самым перерисовав текущий;
    2. jump используется, когда нужно перейти от одного экрана к другому, тем самым отправив этот экран в виде нового сообщения и сохранив предыдущее в истории.

    Например, есть экран First с кнопкой, которая ведет на Second.

    from hammett.core import Button, Screen
from hammett.core.constants import SourceTypes


class First(Screen):
    description = 'This is the first screen'

    async def add_default_keyboard(self, _update, _context):
        return [[
            Button(
                'Next ➡️',
                Second,
                source_type=SourceTypes.MOVE_SOURCE_TYPE,
            )
        ]]

class Second(Screen):
    description = 'This is the second screen'

    async def add_default_keyboard(self, _update, _context):
        return [[
            Button(
                'Back ↩️',
                First,
                source_type=SourceTypes.JUMP_SOURCE_TYPE,
            )
        ]]

    При нажатии на кнопку "Next ➡️" экран First будет перерисован, и на его месте окажется экран Second, т.е. First "сотрется" из истории. Затем, если нажать на кнопку "Back ↩️" на экране Second, First будет отправлен как новое сообщение. В этом случае экран Second сохранится в истории чата.

    См. live-пример бота HammettSimpleJumpBot с демонстрацией работы этого функционала.

    Обработчики#

    Обработчики — это методы экранов, которые вызываются при возникновении определенных событий: нажатие на кнопку, отправка изображения в чат с ботом и т.д.

    Hammett реализует четыре типа обработчиков:

    1. обработчик нажатия на кнопку;
    2. обработчик общего ввода;
    3. обработчик текстового ввода;
    4. обработчик команды (например, /say_hello).

    Чтобы сделать из обычного метода экрана обработчик, этот метод необходимо зарегистрировать. Для этого нужно применить к нему соответствующий декоратор определенного типа и к его аргументу self добавить еще два позиционных аргумента (их порядок важен) — update и context.

    Примечание: обработчики не могут быть статическими методами или методами класса, т.е. обернуты в staticmethod и classmethod соответственно.

    Примечание: независимо от типа обработчика, все они должны возвращать какое-то состояние (см. Состояния), например, DEFAULT_STATE из модуля hammett.core.constants.

    Теперь давайте разберем каждый из этих типов обработчиков по отдельности.

    Обработчик нажатия на кнопку#

    Он содержит код, который будет выполнен при нажатии на ту или иную кнопку.

    Для регистрации обработчика используется декоратор register_button_handler из модуля hammett.core.handlers. После регистрации нужно связать кнопку с обработчиком.

    Кнопки оперируют понятием источник (source) (см. Клавиатура и кнопки). Для того чтобы связать кнопку с ее обработчиком (методом), этот обработчик необходимо указать в качестве источника, т.е. передать его аргументу source при создании кнопки. Также требуется уточнить тип источника через аргумент source_type. В этом случае значением source_type будет HANDLER_SOURCE_TYPE.

    Ниже приведен пример реализации простого кликера, который считает количество нажатий на кнопку.

    from hammett.core import Button, Screen
from hammett.core.constants import SourceTypes
from hammett.core.handlers import register_button_handler


class Clicker(Screen):
    async def add_default_keyboard(self, update, context):
        return [[
            Button(
                'Press to add one point',
                self.add_one_click,
                source_type=SourceTypes.HANDLER_SOURCE_TYPE,
            ),
        ]]

    @register_button_handler
    async def add_one_click(self, update, context):
        context.user_data['num_of_tab'] += 1
        return await self.move(update, context)


    async def get_description(self, update, context):
        return f"You've pressed <b>{context.user_data.get('num_of_tab', 0)}</b> times"

    Примечание: Hammett берет на себя поиск и регистрацию встроенных обработчиков (jump, jump_along_route, move, move_along_route, send и start), т.е. применять к ним декоратор register_button_handler не нужно.

    См. live-пример бота HammettClickerBot с демонстрацией работы этого функционала.

    Обработчик общего ввода#

    Он содержит код, который будет выполнен при вводе какого-либо сообщения от пользователя любого типа, например, при отправке в чат изображения, документа, текстового сообщения, местоположения и т.д.

    Чтобы конкретизировать тип контента, на который обработчик будет срабатывать, нужно в качестве аргумента filters передать ему тип контента из пакета telegram.ext.filters (см. Filters).

    Для регистрации обработчика используется декоратор register_input_handler из модуля hammett.core.handlers.

    Если вы хотите, чтобы этот обработчик срабатывал на определенном этапе/этапах взаимодействия пользователя с ботом, то класс экрана, в котором он определен, следует зарегистрировать только в этом/этих состояниях; в противном случае — во всех имеющихся состояниях (см. Состояния).

    Ниже приведен простой пример бота-репитера, который отправляет пользователю в чат то же изображение, что он получил от него.

    from hammett.core import Screen
from hammett.core.handlers import register_input_handler
from hammett.core.mixins import StartMixin
from telegram.ext import filters


class MyScreen(StartMixin, Screen):
    description = 'Your description'

    async def get_cover(self, update, context):
        if context.user_data.get('photo'):
            return context.user_data['photo']

        return await super().get_cover(update, context)


    @register_input_handler(filters=filters.PHOTO)
    async def handle_photo_input(self, update, context):
        context.user_data['photo'] = update.message.photo[-1]

        return await self.jump(update, context)

    Примечание: если нужно, чтобы обработчик срабатывал на любой тип контента, его следует использовать следующим образом (обратите внимание на пустые скобки при использовании декоратора):

    from hammett.core.handlers import register_input_handler


@register_input_handler()
async def handle_any_input(self, update, context):
    ...

    См. live-пример бота HammettSayHelloBot с демонстрацией работы этого функционала.

    Обработчик текстового ввода#

    Он содержит код, который будет выполнен при вводе какого-либо текстового сообщения от пользователя, например, его имени.

    Для регистрации обработчика используется декоратор register_typing_handler из модуля hammett.core.handlers.

    Этот обработчик является частным случаем register_input_handler, который под капотом использует только текстовый фильтр (см. filters.TEXT).

    Если вы хотите, чтобы этот обработчик срабатывал на определенном этапе/этапах взаимодействия пользователя с ботом, то класс экрана, в котором он определен, следует зарегистрировать только в этом/этих состояниях; в противном случае — во всех имеющихся состояниях (см. Состояния).

    Ниже приведен простой пример бота-репитера, который отправляет пользователю в чат тот же текст, что он получил от него.

    from hammett.core import Screen
from hammett.core.handlers import register_typing_handler


class MeScreen(Screen):
    async def get_description(self, update, context):
        if context.user_data.get('text_input'):
            return (
                f'This is your input:\n'
                f'\n'
                f'{context.user_data["text_input"]}'
            )

        return 'Hey! Try to type something and I will send it back to you!'

    @register_typing_handler
    async def handle_text_input(self, update, context):
        context.user_data['text_input'] = update.message.text

        return await self.jump(update, context)

    Примечание: в примере выше обработчик будет также срабатывать на редактирование ранее отправленных сообщений. Чтобы этого избежать, нужно модифицировать handle_text_input так, чтобы в самом верху была следующая проверка:

    from hammett.core.constants import DEFAULT_STATE


if update.message is None:
    return DEFAULT_STATE

    Таким образом, редактирование будет проигнорировано.

    См. live-пример бота HammettMultiStateBot с демонстрацией работы этого функционала.

    Обработчик команды#

    Он содержит код, который будет выполнен при отправке команды от пользователя, например, /say_hello.

    Для регистрации обработчика используется декоратор register_command_handler из модуля hammett.core.handlers. Декоратор принимает в качестве обязательного аргумента текст будущей команды.

    Примечание: вы можете указать команду как со слэшем (/), так и без него. Оба варианта будут корректно регистрироваться. Например:

    from hammett.core.handlers import register_command_handler


@register_command_handler('say_hello')
async def handle_typing_say_hello_command(self, update, context):
    ...

    или

    from hammett.core.handlers import register_command_handler


@register_command_handler('/say_hello')
async def handle_typing_say_hello_command(self, update, context):
    ...

    Ниже приведен простой пример, который отвечает на ввод команды /say_hello.

    from hammett.core import Screen
from hammett.core.handlers import register_command_handler
from hammett.core.mixins import StartMixin


class StartScreen(StartMixin):
    description = 'This text is sent as a response to the /start command.'


class SayingHi(Screen):
    description = 'This text is sent as a response to the /say_hello command.'

    @register_command_handler('say_hello')
    async def handle_typing_say_hello_command(self, update, context):
        return await self.jump(update, context)

    См. live-пример бота HammettSayHelloBot с демонстрацией работы этого функционала.

    Примечание: если вы захотите ввести команду /say_hello раньше команды /start (т.е. до запуска бота), то обратной реакции от бота не последует.

    Работа с документами#

    Чтобы прикрепить документ к экрану, нужно заполнить атрибут document класса Screen. Он представляет собой типизированный словарь с двумя ключами: media и document_kwargs. Значением media является сам документ в байтовом виде, а document_kwargs — словарь с дополнительными атрибутами объекта InputMediaDocument. С его помощью можно задать имя документа с расширением, передав ключ filename. Все возможные ключи можно посмотреть в документации к InputMediaDocument.

    Ниже представлен пример экрана с документом:

    from hammett.core import Screen


class DocumentScreen(Screen):
    document = {
        'media': b'This is the text of the document.',
        'document_kwargs': {
            'caption': 'This is the first screen',
            'filename': 'Document.txt',
        },
    }

    Примечание: ключ caption отвечает за описание экрана. Если оно не передано, то следующим по приоритету идет атрибут description; если и он не указан, то описание экрана будет пустым.

    Работа с несколькими вложениями#

    Работа с несколькими вложениями требует навыков работы с RenderConfig, о котором пойдет речь дальше в разделе Работа с API.

    Чтобы прикрепить несколько фото или документов (см. Работа с документами) к экрану, нужно передать их в RenderConfig с помощью атрибута attachments, типизации которого описана в модуле hammett.types:

    from collections.abc import Sequence
import telegram


Attachments = (
    Sequence[telegram.InputMediaAudio] | Sequence[telegram.InputMediaDocument] |
    Sequence[telegram.InputMediaPhoto] | Sequence[telegram.InputMediaVideo]
)

    Он представляет собой последовательность с объектами типов telegram.InputMediaAudio, telegram.InputMediaDocument, telegram.InputMediaPhoto или telegram.InputMediaVideo.

    Ниже приведен пример простого экрана с группой из нескольких документов.

    from hammett.core import Screen
from hammett.core.constants import RenderConfig
from telegram import InputMediaDocument
from telegram.constants import ParseMode


class MainMenu(Screen):
    async def get_config(self, _update, _context, **_kwargs):
        return RenderConfig(
            attachments=[
                InputMediaDocument(media=b'123', parse_mode=ParseMode.HTML),
                InputMediaDocument(media=b'123', parse_mode=ParseMode.HTML),
                InputMediaDocument(media=b'123', parse_mode=ParseMode.HTML),
            ],
        )

    Важно: у экрана с группой вложений отсутствует клавиатура.
